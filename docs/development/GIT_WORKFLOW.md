# Git Workflow

## Principles
- Keep the main branch stable.
- Use descriptive branch names when branching is authorized.
- Keep changes focused.
- Review diffs before committing.
- Never commit secrets, credentials, local environments, build output, or private datasets without approval.

## Suggested branch naming
- `feature/<short-description>`
- `fix/<short-description>`
- `docs/<short-description>`
- `test/<short-description>`

## Commit policy
No staging, commit, push, tag, or release action is authorized by this document. Obtain explicit repository-owner approval first.

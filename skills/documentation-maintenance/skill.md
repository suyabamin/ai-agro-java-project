# Skill: Documentation Maintenance

## Trigger
Use after requirements, architecture, APIs, design, tasks, or implementation status changes.

## Workflow
1. Identify the source-of-truth document for the changed information.
2. Update that document first.
3. Update cross-references and related documents.
4. Update `TASKS.md` only with evidence-backed status.
5. Update `MEMORY.md` with verified state and decisions.
6. Add a changelog entry for meaningful changes.
7. Remove contradictions and stale instructions.
8. Do not duplicate full specifications across multiple files.

## Status integrity
Planned, implemented, tested, and verified are distinct states. Preserve that distinction.

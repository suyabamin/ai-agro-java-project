# Future disease model directory

This directory is reserved for a model supplied and trained by the project owner. **It intentionally contains no model weights and no disease labels.** Disease classification remains unavailable until a real artifact is added, metadata is verified, and evaluation is completed.

## Supported v1 model files

- `.keras` Keras v3 single-file model.
- `.h5` Keras HDF5 model.
- SavedModel directories and TensorFlow Lite are not loaded by the current adapter; add a versioned adapter before registering those formats.
- TensorFlow is an optional inference dependency, not installed by the base FastAPI service. The model loader returns a safe load-failed/unavailable state if TensorFlow is absent.

## Directory layout

```text
ai model/
  README.md
  metadata.schema.json
  labels.schema.json
  active.json                 # created only when an evaluated model is supplied
  <model-version>/
    model.keras               # supplied model; never generated by this repository
    metadata.json
    labels.json
```

`active.json` contains `{ "directory": "<model-version>" }`. The directory must be a direct child of this directory. Path traversal and symlink escapes are rejected. `metadata.json` uses `metadata.schema.json`; its model and label SHA-256 hashes are verified before model loading. Label indexes must be contiguous from zero and match model output width.

## Input contract

The user-supplied model metadata declares exact `width` and `height`, three channels, `RGB` color order and one normalization mode:

- `NONE`: float32 values in the decoder's 0–255 range.
- `ZERO_ONE`: divide RGB values by 255.
- `MINUS_ONE_TO_ONE`: map RGB values to [-1, 1].
- `MEAN_STD`: subtract three declared channel means and divide by three positive channel standard deviations.

OpenCV decodes untrusted image bytes in memory, rejects unsupported/corrupt inputs and excessive dimensions, converts BGR to RGB, resizes to the declared input geometry, and applies only the declared normalization. The pipeline does not infer a model contract from a filename or architecture name. Original upload bytes are retained by the storage layer; preprocessing produces an in-memory tensor only.

## Metadata and evaluation requirements

`metadata.json` must include schema version, model name/version, supported model filename, model SHA-256, label-map filename and SHA-256, output activation (`SOFTMAX` or `LOGITS`), input contract, and evaluation record. Evaluation includes dataset name/license, evaluation date, validation split, metrics, and known limitations. Runtime loading requires `evaluation.status = EVALUATED`; a model without real evaluation evidence cannot become available.

The checksum proves artifact identity, not model safety, provenance, accuracy, or licensing. Keep the original training/evaluation report and dataset license with the model submission and have them reviewed before registration. The service reports the raw top output as an uncalibrated model score; it is not described as the probability of correctness.

## Registration and loading

1. User supplies the trained artifact, actual `labels.json`, metadata, checksum values, license/provenance and evaluation report.
2. Verify input size/color/normalization compatibility against preprocessing and output shape against labels.
3. Update `active.json` to the reviewed model-version directory.
4. Install the optional TensorFlow runtime required by the supplied artifact.
5. Restart/reload the AI service and verify the reported model name/version and checksum.
6. Run held-out integration/evaluation tests on the actual model before enabling inference for users.

No model training, dataset selection/preparation, accuracy evaluation, or production model deployment is included in Milestone 6 infrastructure work.
